# Дримворлд Навсегда — лаунчер

Лаунчер для сервера **Дримворлд Навсегда** (WoW Forever, TrinityCore forever).

Репозиторий основан на открытом launcher из проекта
[`jibay442/forever_docker`](https://github.com/jibay442/forever_docker) (GPL-2.0).
Он устанавливает и обновляет клиент, выполняет вход через LoginREST bnetserver,
подставляет ключ сервера и запускает `Wow.exe`.

## Что делает

1. Находит клиент или устанавливает его в папку рядом с лаунчером.
2. Обновляет клиент по манифесту и проверяет SHA-256.
3. Логинится на `https://trinity.actual.mmolabs.ru:8081` по email и паролю.
4. Запоминает сессию на 30 дней.
5. Подставляет ключ сервера в память клиента и запускает игру.

Кнопка запуска имеет три состояния: **Играть** (клиент готов),
**Обновить** (клиент устарел) и **Установить** (клиента нет).

## Сборка

GitHub Actions, Windows only: `.github/workflows/launcher.yml`.
Результат — `Forever AI.exe` и NSIS-установщик.

Локально (Windows):

```powershell
cd app
npm install -g @tauri-apps/cli@2
npx @tauri-apps/cli@2 build --bundles nsis
```

## SteamOS / Steam Deck (AppImage)

Отдельная сборка `Forever-AI-SteamOS.AppImage` (job `linux` в workflow,
собирается на `ubuntu-22.04`). Свой WebKitGTK лежит внутри AppImage, системный
WebView2 не нужен; через Proton запускаются маленький PE64-помощник и `Wow.exe`.

- Proton берётся из Steam (Библиотека → Инструменты → Proton) или GE-Proton.
  Запуск: `proton run` с `STEAM_COMPAT_DATA_PATH`. Отдельный системный Wine не нужен.
- Префикс по умолчанию: `~/Games/forever-wow`.
- `hosts` и установка CA не нужны: портал `trinity.actual.mmolabs.ru`
  резолвится публичным DNS, сертификат Let's Encrypt проверяется системным
  хранилищем (Wine сам импортирует корневые сертификаты хоста в префикс).
- Клиент (`_forever_`) ставится рядом с AppImage.
- Автообновление: `launcher_manifest_linux.json`, публикация —
  `wowserver/scripts/publish-launcher-steamos.sh`.
- Для Game Mode: «Добавить стороннюю игру» → AppImage, параметр запуска `--play`.
  **Не включайте принудительную совместимость Proton для самого AppImage**:
  лаунчер нативный и запускает выбранный Proton самостоятельно.

Ключ записывает `forever-keypatch.exe` через `ReadProcessMemory`/`WriteProcessMemory`
в том же Wine/Proton-префиксе. Помощник сам запускает игру, отслеживает её процесс
и дочерний клиент, проверяет полное хранилище 12 × 40 байт перед записью и после неё.
Неизвестные ключи, неоднозначные кандидаты и неполные чтения не разрешают запись.
После успешной установки проверяются только 480 байт, а не вся память.
Начиная с 1.4.10 адреса структур-кандидатов сохраняются после полного прохода:
если ID уже есть, а ключи ещё не инициализированы, эти адреса проверяются каждые
25 мс, в том числе во время следующего большого сканирования. Это не ослабляет
проверку ключей и единственности кандидата. Переполнение индекса запрещает запись
до полного повторного построения. Полное сканирование неизвестных структур
выполняется реже; обнаружение нового адреса всё ещё может потребовать полного прохода.
`LD_PRELOAD`, root, отключение Yama и запись в исполняемый файл не используются.

При каждом запуске создаются отдельные `keypatch.log` и `proton.log` в
`~/.config/forever-launcher-app/runs/<идентификатор>/` (или `$XDG_CONFIG_HOME`).
Их полные пути выводятся в журнале лаунчера сразу после запуска.
`READY ... verified=1` означает проверенную запись ключа, **не** подтверждение входа в мир.
Строки содержат `t_ms` от запуска помощника и `utc`, чтобы сравнить момент записи
с ошибкой в журнале подключения игры. Если первая попытка была до `READY`,
может понадобиться «Переподключиться» в клиенте: помощник не управляет интерфейсом WoW.
При потере связи с помощником лаунчер предупреждает и не разблокирует повторный
запуск автоматически: сначала закройте оставшуюся игру и перезапустите лаунчер.

Для сборки PE64-помощника нужен пакет `gcc-mingw-w64-x86-64` (только на машине сборки).
Локально: `cargo install tauri-cli --version "^2" --locked`, затем
`cd app && cargo tauri build --bundles appimage`.

Тесты помощника без сервера и учётных записей:

```sh
cc -std=c11 -Wall -Wextra -Werror -fsanitize=address,undefined app/linux/test_keystore.c -o /tmp/test-keystore
/tmp/test-keystore
PROTON=/path/to/proton xvfb-run -a python3 app/linux/test_proton.py
```

Тесты создают отдельный временный префикс и синтетический `Wow.exe`; проверка
реального входа на сервер всё равно требует Steam Deck/Steam Machine.

## Сертификат

Портал использует публичный сертификат Let's Encrypt; отдельная установка CA
и правка `hosts` не требуются.

## Новости в лаунчере

Лаунчер читает `https://forever.mmolabs.ru/launcher/news.json`, сортирует
записи по дате (новые сверху) и показывает:

- **главный экран** — самую свежую новость крупным блоком: дата, тег,
  заголовок, краткое описание и картинка (если указана);
- **внизу справа** — карточки трёх следующих публикаций;
- **«Все новости»** — список всех публикаций.

Клик по новости или кнопке «Читать полностью» открывает полный текст в окне
лаунчера, браузер не используется. Если файл недоступен, показываются заглушки
из `i18n.js`.

Формат записи:

```json
{
  "title": "Заголовок",
  "tag": "Лаунчер",
  "date": "2026-11-12",
  "summary": "Краткое описание для главного экрана и карточек",
  "text": "Полный текст новости.\n\nАбзацы разделяются пустой строкой.",
  "image": "https://forever.mmolabs.ru/news/1.jpg"
}
```

`tag`, `date`, `summary`, `text`, `image` необязательны. Если `summary` нет,
на главном экране показывается первый абзац `text`. Относительные ссылки на
картинку склеиваются с адресом сайта. Файл лежит в
`/srv/forever-launcher/news.json` (и в
`osconfig/srv/forever-launcher/news.json`), отдаётся nginx без кеша.

## Обновление клиента

Лаунчер проверяет `https://forever.mmolabs.ru/launcher/manifest.json`,
скачивает недостающие/изменённые файлы, проверяет SHA-256 и атомарно заменяет
их. Клиентские данные раздаются нашим сервером; Blizzard CDN для игроков не
используется. Аддоны в лаунчер не входят — игроки ставят их самостоятельно.

## Автообновление лаунчера

При запуске лаунчер читает `launcher_manifest.json` с сайта сервера. Если там
версия новее, появляется баннер «Доступно обновление лаунчера». По кнопке
лаунчер скачивает новый EXE, проверяет размер и SHA-256, запускает helper,
выходит, заменяет свой файл и перезапускается. Пароль и настройки при этом не
теряются.

Автообновление работает в Windows-версии. Первый переход на версию с
автообновлением (1.1.2) нужно один раз выполнить вручную: в более старых
версиях этого кода ещё нет.

## Проверка готовности ПК

Проверки в настройках оставлены для диагностики. Для рабочего портала
`trinity.actual.mmolabs.ru` hosts и приватный CA не нужны.

## Сервер

Лаунчер работает только с нашим сервером; адрес, портал и сайт не редактируются.
Портал — `trinity.actual.mmolabs.ru`, сертификат Let's Encrypt проверяется
системным хранилищем.

## Патч портала

`Wow.exe` патчится **на сервере**: `scripts/patch-client-portal.py` заменяет
18-байтовый суффикс `.actual.battle.net` на `.actual.<домен>` после каждого
обновления клиента. Лаунчер получает уже готовый файл через манифест.

Для `Wow.exe` в манифесте стоит `verify_sha256: true`: размер патченного файла
не меняется, поэтому лаунчер дополнительно сверяет SHA-256 и скачивает новую
версию, даже если размер совпадает. Игрок не заменяет файлы вручную.

## Установка клиента с нуля

В «Настройки → Игра» выберите пустую папку (корень установки, не `_forever_`)
и нажмите «Скачать клиент». Лаунчер скачает все файлы из манифеста (~54 ГБ),
проверит SHA-256, создаст `_forever_` и `Data`, после чего сам переключит
`game_dir` на `_forever_/Wow.exe`. Если часть клиента уже есть, скачаются
только отсутствующие/несовпавшие файлы.

## Проверка клиента

Кнопка «Обновить» на главном экране делает быструю проверку: сравнивает размеры
файлов (и SHA-256 для `Wow.exe`) и скачивает только отличающиеся.

Кнопка «Проверить клиент» в настройках запускает полную проверку: читает и
хэширует все файлы клиента, находит повреждённые/подменённые файлы с тем же
размером и восстанавливает их с сервера. Это занимает заметно больше времени.
