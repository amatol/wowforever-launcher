# Самообновление лаунчера с 1.4.30

- Общего лимита времени загрузки EXE/AppImage нет: медленное, но активное
  соединение может работать сколько требуется.
- Таймаут установления соединения — 30 секунд; ожидания HTTP-ответа и
  очередной порции данных — 120 секунд. Это ограничения простоя, а не
  общей длительности скачивания.
- При сетевых ошибках, неполном ответе или HTTP-ошибке выполняются до
  50 повторов через 5 секунд. Получение манифеста при установке также
  повторяется. Проверка наличия обновления остаётся коротким запросом.
- Частичный файл хранится рядом с запускаемым лаунчером:
  `.<имя лаунчера>.update-<SHA-256>.part`. Имя не зависит от PID и
  переживает закрытие/перезапуск. Разные артефакты не склеиваются.
- Докачка — HTTP Range от фактической длины файла. Для 206 проверяется
  точный Content-Range и размер. Если сервер игнорирует Range и отдаёт
  200, файл записывается с начала, а не дописывается. Неверный диапазон
  не меняет сохранённый префикс. Ответ 416 сбрасывает загрузку.
- До установки обязательно проверяются полный размер и SHA-256 всего
  файла, включая сохранённый префикс. Повреждённая копия сбрасывается и
  скачивается заново. При исчерпании повторов корректная частичная
  загрузка остаётся на диске для следующего запуска.
- Журнал и --play показывают докачку, процент, объём, повторы, проверку
  SHA-256 и ошибки. Рабочий лаунчер не заменяется до завершения проверки.
- Важно: новая логика начинает действовать только после установки 1.4.30.
  Версия 1.4.28 не может воспользоваться исправлением заранее. При
  невозможности первого автообновления надо один раз скачать новый
  AppImage/EXE браузером с докачкой и заменить прежний файл после закрытия.

Переход всего клиента на Yandex остаётся выключенным до исправления
недоступных объектов. Он требует отдельного `yandex.all_files: true` в
client_build.json, отсутствующего в текущей рабочей конфигурации.

Проверки: `cargo test --lib` (локальный HTTP-сервер: обрыв, 206/200/416,
ошибочный диапазон, повреждённый SHA-256, исчерпание повторов, повторный
запуск и медленная активная передача дольше таймаута простоя).
