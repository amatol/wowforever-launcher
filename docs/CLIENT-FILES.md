# Служебные и скрытые файлы лаунчера

Проверено по исходникам 1.4.31, **22.11.2026**. Все пути ниже, если не указано
иное, находятся в папке клиента рядом с `Data` и `_forever_`.

## Маркеры состояния

Один файл `.forever_state.json` в папке клиента:

```json
{
  "manifest_version": "20261116-2",
  "data_revision": "20261116-1"
}
```

- `manifest_version` — версия установленного манифеста.
- `data_revision` — ревизия набора `Data`. Не совпала с манифестом —
  `Data` заменяется целиком.

Файл пишется только после успешной установки. При первом запуске 1.4.31
старые `.launcher_version`, `.forever_data_revision` и
`.forever_full_reinstall` автоматически переносятся в него и удаляются.
Полной обязательной переустановки в 1.4.31 больше нет: обновляется только
изменившийся набор, а при смене `data_revision` заменяется каталог `Data`.

## Временные каталоги обновления

| Путь | Назначение |
|---|---|
| `.forever-update-<ревизия>` | Staging замены `Data` при новой `data_revision`; содержит полный проверенный набор. |
| `.forever-old-data-<ревизия>` | Прежняя `Data` на время замены. Если осталась после сбоя, лаунчер останавливается и просит ручную проверку. |
| `.forever-update-<версия>` | Устаревший staging полной переустановки из версий до 1.4.31. Новыми версиями не создаётся. |
| `.forever-old-data-<версия>`, `.forever-old-forever-<версия>` | Устаревшие каталоги полной переустановки до 1.4.31. Новыми версиями не создаются. |

Старые staging-папки **не удаляются автоматически**: в них могут остаться
единственные копии пользовательских файлов. Удалять только вручную, при
закрытом лаунчере и после проверки содержимого.

## Пользовательские резервы

`.forever-user-backups/<время>/` — резервы `WTF`, `Interface`,
`_forever_/WTF` и `_forever_/Interface`, которые создавали версии до 1.4.31
перед полной переустановкой. Новые версии этот каталог не создают: `_forever_`
больше не заменяется целиком, поэтому настройки остаются на месте. Старые
резервы автоматически не удаляются.

## Частичные загрузки

| Путь | Назначение |
|---|---|
| `.<имя файла>.part` | Неполная загрузка обычного файла клиента; лежит рядом с целевым файлом внутри staging. |
| `.<имя лаунчера>.update-<SHA-256>.part` | Постоянная докачка самообновления EXE/AppImage, рядом с лаунчером. Не зависит от PID и переживает перезапуск. |

Обычные `.part`-файлы безопасно удалять для повторной загрузки. Частичный
файл самообновления лучше сохранить: он позволяет продолжить на медленной
связи. Перед установкой всё равно проверяются полный размер и SHA-256.

## Проба записи и игровые скрытые файлы

- `.forever-launcher-write-<PID>` — пустая проба прав на запись в папку
  лаунчера; создаётся и сразу удаляется. Остаток возможен только после
  аварийного завершения.
- `.build.info` — файл игры, входит в манифест; лаунчер читает из него
  установленную сборку и обновляет его как обычный клиентский файл.
- `_forever_/.flavor.info`, `Data/wowf/.residency` — игровые файлы из
  манифеста, лаунчер их скачивает, но не создаёт сам.

## Не скрытые файлы настроек лаунчера

Настройки и сессия хранятся отдельно от клиента: `settings.json` и
`session.json` в каталоге `forever-launcher-app` внутри системного каталога
конфигурации. На Linux это `~/.config/forever-launcher-app/`, на macOS —
`~/Library/Application Support/forever-launcher-app/`, на Windows — `%APPDATA%`.
